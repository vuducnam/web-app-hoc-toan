## Overview

- **Priority:** P2 (blocker for 02-06)
- **Status:** pending
- **Effort:** ~2h
- Add 6 nullable `String` (Markdown) columns: 3 on `Lesson`, 3 on `Skill`. Update seed types. Generate Prisma client.

## Key Insights

- Postgres `text` is unbounded → fine for MD blocks (typical 200-2000 chars)
- Nullable per-section: skipping a section is "no override" (use lesson default), null on lesson means "no content"
- No new index needed: notes are read by `lesson.id` / `skill.key` which already have indices
- Migration is purely additive → zero downtime, zero existing-row impact
- Naming uses `knowledgeNote*` prefix (NOT `note*`) to avoid collision with future generic note systems and stay greppable

## Requirements

### Functional
- `Lesson` gains: `knowledgeNoteRemember`, `knowledgeNoteCaution`, `knowledgeNoteExtension` (all `String?`)
- `Skill` gains: same three columns (override semantics)
- Prisma client regenerates with new fields available on Lesson/Skill types
- Seed types in `prisma/seed-data/types.ts` extend `SeedLesson` + `SeedSkill` to optionally carry these fields

### Non-Functional
- Migration is reversible (down migration drops the 6 columns)
- No data conversion needed (additive only)

## Architecture

### Data Flow
```
Author writes Markdown in seed-data/grade-4.ts
  → seed.ts upserts Lesson with knowledgeNote* fields
    → Postgres stores TEXT
      → Practice page Prisma query selects them
        → Phase 02 resolver merges skill/lesson
          → Phase 03 renders to UI
```

### TS Type Diff (target — `prisma/seed-data/types.ts`)
```ts
// Optional knowledge-note fields (null/undefined = use lesson default for skills,
// or "no content for this section" for lessons).
export interface KnowledgeNoteFields {
  knowledgeNoteRemember?: string | null;
  knowledgeNoteCaution?: string | null;
  knowledgeNoteExtension?: string | null;
}

// SeedLesson now carries default notes for the lesson
export interface SeedLesson extends KnowledgeNoteFields {
  order: number;
  nameVi: string;
  skills: SeedSkill[];
}

// SeedSkill (both branches of XOR) gain optional override notes
// — apply intersection to existing discriminated union
```

## Implementation Steps

1. Pull latest main; ensure DB is up (`npm run db:up`)
2. Edit `prisma/schema.prisma`: add 3 columns each to `Lesson` (after `nameVi`) and `Skill` (after `timeEstimateSec`)
3. Run `npm run db:migrate -- --name add-knowledge-notes` → creates migration SQL + regenerates client
4. Edit `prisma/seed-data/types.ts`:
   - Add `KnowledgeNoteFields` interface
   - `SeedLesson` extends it
   - Both branches of `SeedSkill` discriminated union extend it
5. Edit `prisma/seed.ts`:
   - In `upsertLesson`: include `knowledgeNoteRemember/Caution/Extension` in `create` and `update` data
   - In `upsertSkill`: same three fields
   - Default to `null` when undefined (preserve existing behaviour for current seeds)
6. Run `npm run db:seed` — should be no-op for existing data; confirm no errors
7. `npm run typecheck` — must pass
